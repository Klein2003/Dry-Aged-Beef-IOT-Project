# dry aged beef IOT
## อุปกรณ์
- sensor วัดความชื่นและอุณหภูมิ
- sensor ตรวจจจับวัตถุ
## ข้อมูลต่างๆ
- ลักษณะของเครื่องจะเป็น ตู้ที่จะมีทั้งหมด 3 ชั้น แต่ละชั้นจะมีอยู่ 3 ช่องซึ่งแต่ละช่องจะมี sensor เป็นของตัวเอง
- การทำงานคือ ถ้าช่องไหน sensor ตรวจจับพบเนื้ออยู่ในช่อง ตู้จะรักษาอุณหภูมิและความชื้นของช่องที่มีเนื้อให้อยู่ในช่วงที่เหมาะสม คือ อุณหภูมิ ต้องอยู่ระหว่าง 1°C ถึง 3°C (หรือ 34°F - 38°F) และ ความชื้นสัมพัทธ์ ควรอยู่ที่ 75% ถึง 85%
แต่ถ้าอุณหภูมิและความชื้นของช่องนั้นมีมากกว่าหรือน้อยกว่าคช่วงที่เหมาะสมมันจะไปสั่งให้ตู้ปรับอุญหภูมิใหม่พร้อมส่งการแจ้งเตือนไปหาผู้ใช้ โดยที่จะบอกว่า ตอนนี้อุณหภูมิหรือความชื้นของเนื้อในช่องนั้นๆต่ำหรือสูงกว่าช่วงที่กำหนดไปเท่าไรและเกิดตอนไหน พร้อมบอกว่าตอนนี้สถานะปัจจุบันของอุณหภูมิและความชื้นของช่องนั้นเป็นยังไงแล้วบ้าง

## MQTT + SQLite
### ฝั่ง ESP32 (Wokwi, MicroPython) — โฟลเดอร์ `wokwi/`
- `main.py`, `ssd1306.py`, `diagram.json` คัดลอกไปวางในโปรเจกต์ Wokwi ได้เลย
- ESP32 บอร์ดเดียวดูแลครบ 9 ช่อง (3 ชั้น x 3 ช่อง) แต่ละช่องมี DHT22 + HC-SR04 ของตัวเอง

| ช่อง | 1-1 | 1-2 | 1-3 | 2-1 | 2-2 | 2-3 | 3-1 | 3-2 | 3-3 |
|---|---|---|---|---|---|---|---|---|---|
| DHT22 (SDA) | 14 | 4 | 5 | 16 | 17 | 18 | 19 | 25 | 26 |
| HC-SR04 ECHO | 32 | 34 | 35 | 36 (VP) | 39 (VN) | 27 | 21 | 22 | 23 |

- TRIG ของ HC-SR04 ทุกตัวต่อร่วมกันที่ขา 33, OLED SDA=12 / SCL=13, ไฟสถานะ NeoPixel 3x3 ที่ขา 15
- มีเนื้อ = HC-SR04 วัดระยะได้ 0-100 ซม.
- ไฟสถานะ (1 ดวงต่อ 1 ช่อง): เขียว = มีเนื้อและปกติ, แดง = ไม่มีเนื้อ, เหลืองกระพริบ = ค่าหลุดเกณฑ์
- OLED: บรรทัดบนแสดงจำนวนช่องที่มีเนื้อ + สถานะ MQTT, ตาราง 3x3 (`OK` ปกติ, `--` ว่าง, `!T` อุณหภูมิผิด, `!H` ความชื้นผิด, `!!` ผิดทั้งคู่) และสลับแสดงค่าละเอียดทีละช่อง (ช่องที่ผิดปกติแสดงก่อน)
- ส่งค่าทุกช่องขึ้น MQTT ทุก 5 วินาที และถ้าหลุดจะเชื่อมต่อใหม่เอง
  - topic: `dryaged/cabinet1/slot/<ชั้น>-<ช่อง>` เช่น `dryaged/cabinet1/slot/2-3`
  - payload: `{"shelf": 2, "slot": 3, "meat": true, "temp": 2.1, "hum": 80.3}`
  - สถานะเครื่อง: `dryaged/cabinet1/status` = `online` / `offline` (LWT)
- ถ้าต่อวงจรจริง: HC-SR04 ใช้ไฟ 5V ขา ECHO ต้องมีวงจรแบ่งแรงดันลงเหลือ 3.3V ก่อนเข้า ESP32 และการใช้ TRIG ร่วมกันทำให้ทุกตัวยิงคลื่นพร้อมกัน ถ้าช่องอยู่ใกล้กันอาจรบกวนกัน ควรมีผนังกั้นแต่ละช่อง

### ฝั่ง Python
- `app.py` dashboard (เลือกแหล่งข้อมูลได้ว่าจะใช้ MQTT จาก ESP32 หรือโหมดจำลอง)
- `mqtt_bridge.py` รับข้อมูลจาก MQTT แล้วส่งให้ `storage.py` บันทึกลง SQLite
- รัน: `streamlit run app.py` (หรือ `python mqtt_bridge.py` ถ้าจะเก็บข้อมูลอย่างเดียวโดยไม่เปิดหน้าเว็บ — อย่ารันทั้งสองแบบพร้อมกันกับ DB ไฟล์เดียวกัน ไม่งั้นข้อมูลจะถูกบันทึกซ้ำ)
- ตั้งค่าได้ด้วย env หรือ `.streamlit/secrets.toml`: `MQTT_HOST`, `MQTT_PORT`, `MQTT_TOPIC_BASE`, `MQTT_USERNAME`, `MQTT_PASSWORD`, `DB_PATH`, `HOURLY_LOG_SEC`, `ALARM_LOG_SEC`
- ถ้าใช้ broker สาธารณะ (broker.hivemq.com) ควรเปลี่ยน `TOPIC_BASE` / `MQTT_TOPIC_BASE` ให้ไม่ซ้ำกับคนอื่น

### การเก็บข้อมูล (SQLite `dryaged.db`)
- เก็บ **เฉพาะช่องที่ตรวจพบเนื้อ** และ**แต่ละช่องแยกตาราง** `slot_1_1` … `slot_3_3`
- คอลัมน์: `id, ts, temp, hum, record_type, detail`
- `record_type`
  - `hourly` — เก็บทุก 1 ชั่วโมง
  - `out_of_range` — เก็บทันทีที่อุณหภูมิ/ความชื้นออกนอกเกณฑ์ และเก็บซ้ำทุก 60 วินาทีระหว่างที่ยังผิดปกติ (หรือเมื่อปัญหาเปลี่ยน) `detail` จะบอกว่าสูง/ต่ำกว่าเกณฑ์เท่าไร
  - `back_to_normal` — เก็บตอนที่ค่ากลับเข้าเกณฑ์
- ดูข้อมูลและดาวน์โหลด CSV ได้ที่แท็บ "🗄️ ข้อมูลที่บันทึก (SQLite)" ใน dashboard
